Token budgets that hold.

Hardcap is an LLM gateway that enforces per-tenant token budgets across any number of replicas without overshooting. The load tests that prove it ship with the code.

The problem

Counting tokens after the response is a budget in name only.

An LLM request can cost 10 tokens or 100,000, and output length is only known when the stream ends. So most gateways check used < limit on admission and add the real count afterwards. Between those two moments, a request is invisible to the budget: with 128 streams in flight, all 128 get admitted while the tenant still looks under budget. More replicas make it worse.

How it works

Authorize, then capture, the way card payments do.

Each step is a single Lua script in Redis. Redis runs one script at a time, so for any tenant the checks and updates are serialized, however many gateway replicas send them.

01 · admit.lua

Reserve before the call

Checks the request rate, reclaims reservations left by crashed replicas, and reserves input plus estimated output tokens. One round trip; a rejected request costs nothing.

-- atomic, per tenant
if used + reserved + est > limit
  then return busy | exceeded
reserved += est
02 · extend.lua

Grow it while streaming

The estimate is the rolling p95 of real output lengths. As a stream nears its reservation, the gateway asks for 64 more tokens. If the budget can't cover them, the stream ends with finish_reason: "length".

-- every 64 tokens
if used + reserved + 64 > limit
  then truncate
reserved += 64
03 · settle.lua

Charge the real count

The reservation is swapped for the usage the provider reported, and cost is attributed per tenant, route and model in Prometheus.

-- when the response ends
reserved -= reservation
used     += actual
used + reserved ≤ limit

Checked inside every admit and extend. Settlement swaps a reservation for the real count, so the budget can only be exceeded by tokens generated without a reservation, and truncate mode allows none.

What's in v0.1

A small gateway that does one hard thing well.

Per-tenant token budgets

Input, output and total limits per window, enforced across stateless replicas.

Rate limits in the same script

Sliding-window counter or token bucket, checked atomically with the budget.

Busy vs. spent

budget_busy (retry in 1 s) is kept separate from budget_exceeded (retry when the window resets).

Fallback and circuit breakers

Ordered fallback on 429, 5xx, timeouts and connection errors, with a breaker per upstream.

OpenAI and Anthropic

An OpenAI-compatible API in front of OpenAI, vLLM and other compatible servers, plus Anthropic, translated both ways.

Cost attribution

Prometheus metrics per tenant, route and model, plus a ready-made Grafana dashboard.

Use Hardcap when

  • Several teams or customers share one LLM bill and a budget has to mean a hard limit.
  • You run more than one gateway replica and need limits that hold across all of them.
  • You want to see the evidence and rerun it on your own hardware.

Look elsewhere when

  • You need 100+ providers behind one API: LiteLLM covers far more.
  • You need raw throughput above a few thousand req/s per node: v0.1 is Python.
  • You need an admin UI or hosted service. Hardcap is config files and metrics.
Quickstart

Running in a minute, no API key needed.

The built-in mock LLM lets you try budgets, truncation and fallback locally. Then point any OpenAI SDK at Hardcap and use a tenant key as the API key.

# install and run against the mock LLM
pip install hardcap
docker run -d -p 6379:6379 redis:7-alpine
curl -sO https://raw.githubusercontent.com/saikirankalidindi/hardcap/main/examples/local.yaml
hardcap mock --port 9001 &
hardcap serve -c local.yaml
# any OpenAI client works
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8080/v1",
                api_key="sk-alpha")  # a tenant key
client.chat.completions.create(
    model="demo", stream=True,
    messages=[{"role": "user", "content": "hi"}])
# config.yaml: one tenant, one route with fallback
budget: {accounting: reserve, estimator: p95, on_overrun: truncate}
upstreams:
  openai:    {kind: openai, base_url: https://api.openai.com, api_key_env: OPENAI_API_KEY}
  anthropic: {kind: anthropic, base_url: https://api.anthropic.com, api_key_env: ANTHROPIC_API_KEY}
routes:
  default: {targets: [{upstream: openai, model: gpt-4o-mini}, {upstream: anthropic, model: claude-haiku-4-5}]}
tenants:
  search-team: {api_keys: [sk-hc-search], budget: {window_s: 3600, total: 2000000}}
